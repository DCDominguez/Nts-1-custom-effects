# FIELD 0.1-1 internal audit before 0.1-2

## Status
2026-09-11; branch field-0.1-0-test; source d9a062af445d54544d4c563cff733ef4b1886bfd, matching live PR #10 head. FIELD remains 0.1-1. No DSP changes or device build. Classification: FAIL / RETEST for consecutive-note hardware behavior; proposed remedies DESIGN ONLY.

## Why
DC reports only C echoes from C-D-E spaced approximately half a second apart. DC approved clock-spaced captures in principle, requested an internal audit first, and requires pausing before additional improvements.

## What changed
Added observational host diagnostic tests/lattice-field/audit_0_1_1.cpp and this report. Component probes explicitly seed internal state for stereo and alias analysis; those are not end-to-end hardware tests.

## Findings and reproduction
Compile: g++ -std=c++11 -O2 -I tests/lattice-field/stubs tests/lattice-field/audit_0_1_1.cpp -o /tmp/lattice-audit
Run: /tmp/lattice-audit

- Equal-amplitude continuous C-D-E-like pitch steps every 500 ms: only one capture admitted. Separated 125 ms notes every 500 ms: three admitted. Consistent with an envelope-trigger limitation, but the user's exact source envelope remains unknown.
- 100 ms notes every 250 ms for six seconds, 120 BPM and slowest CLOCK: 24 admitted, zero voices spawned while playing; four spawned after two seconds of silence. Replacement can starve every first response. Clocked recapture alone can exacerbate this.
- First response is scheduled at capture birth + capture length + tick, rather than birth + tick. Capture length caps at 4096 samples (85.33 ms at 48 kHz). At 120 BPM and a quarter-second tick, scheduling is about 335 ms after admission. Treat whether this extra latency is desired as a design decision.
- Sine peaks .005 and .010 FS did not admit; .020 FS and above did in the tested range. Fixed gate sensitivity misses quiet input.
- A linear 500 ms sine attack to .4 FS produced first-capture RMS .037674, 17.51 dB below the eventual .282843 RMS. Brief capture of a slow onset can yield quiet echoes despite foreground boost.
- Ping-Pong balances the original channels rather than routing between them. A left-only capture has zero right clear output on both first and second events; left RMS .282893 then .050921 in the isolated pan probe (before event-level multiplication). Bloom may still spread; this finding concerns clear echoes.
- An isolated octave-up ghost from an 18 kHz source generates a 12 kHz alias, amplitude .157767 before ghost envelope/level, -8.08 dB relative to .4 source. Post-resampling low-pass does not prevent aliasing. Audible significance is untested.
- Host stub MIX enum is 2; real Korg SDK uses 3 because of reserved0. Verified both local pinned SDK f6f073bb83d5ef69310fca609c41ddcf722dd558 and current official GitHub header (blob 692afcb743c28c748528ecb439126a331be6eed1). Production compiles against the real header; do not attribute hardware failure to the stub.
- Block sizes 1/16/32/64 gave identical output energy, bloom state hash, capture and spawn counts for the tested signal.

## Runtime, headroom and checks
Existing suite passed all 32 mode/division lifecycle cases, ownership/control sweeps, wrap, invalid-state containment, ordinary headroom and rest checks under ASan/UBSan. LeakSanitizer initially failed because this environment uses ptrace; reran with ASAN_OPTIONS=detect_leaks=0. This does not establish leak-check success. Ordinary-input output peak .445093; no wet guard hits. Existing dense test checks admission, not first-response delivery, so it misses the reproduced starvation. No new CPU measurements; MkI runtime margin remains unknown.

## Physical result
Only user evidence: isolated notes/chords echo; subsequent corrections established faint but audible delays; after 0.1-1, C-D-E yielded only C. No new hardware test in this audit. Do not equate the host reproduction with proof of the exact hardware cause.

## Sound-quality intent and proposed next step
Recommend approval of clocked capture plus protection until a seed's first clear answer completes. With two occupied protected buffers, skip admissions rather than overwrite unheard phrases; this deliberately samples busy input rather than promising every note. Correct test enum and add delivered-response assertions alongside that work. Preserve gain, ghosts, bloom and existing timing for isolation unless separately approved.

Present soft-onset sensitivity, clock offset, stereo routing and alias findings as separate decisions; no implementation yet. Under a fixed two-seed budget, continuous captures, slow response timing and delivery of every note cannot all be guaranteed. Additional capture storage/queueing would be a separate architecture proposal.
