# FIELD 0.1-2 — clocked captures and delivered first answers

## Status
2026-09-11, field-0.1-0-test; baseline d9a062af445d54544d4c563cff733ef4b1886bfd; preceding audit 4317113. User approved this build and the basic three-layer protocol. Classification: DESIGN ONLY pending ARM compilation, then BUILD ONLY pending physical MkI testing. Exact built source SHA is recorded by CI in BUILD-PROVENANCE.txt.

## Why
Hardware C-D-E reportedly echoed only C. Host tests reproduced missed equal-amplitude pitch changes and slow-clock replacement starvation. Admission counts alone were an inadequate regression criterion.

## What changed
- Added recapture countdown at current CLOCK/host tempo, minimum 5760 samples (120 ms); retained attack/rearm detection and 120 ms refractory. CLOCK cadence is relative to admission attempts, not an externally phase-locked transport grid.
- Both captures are protected until their first clear voice finishes. Replacement selects the oldest eligible capture and retains the existing 96-sample retirement fade. When neither is eligible, skip the attempt; no queue. First voices are excluded from capacity-steal victims.
- Qualifying sustained input now replenishes phrases; no FIELD wet-to-capture route. Every admitted seed keeps its fixed deadline. CORE frozen audio remains incoming input.
- Corrected desktop MIX ABI enum to include Korg reserved ID 2 and MIX ID 3; literal-ID test added. Device header already used correct values.
- Added completed-first-answer and wet-output checks during busy input for all 32 mode/division combinations, and a legato C-D-E pitch/actual-output check.
- Updated reporting/testing protocol, current spec/system amendment, history, README, CI packaging and focused hardware QA.

## Sound-quality intent
Consecutive and sustained input should keep producing selected audible answers; no unheard phrase should be replaced. Two captures do not guarantee every note repeats at slow clocks. Later answers/ghosts can still be cut short by clean replacement. Preserve 0.1-1 gain, bloom network/sends, voice levels, mode tables and timing offsets. Soft-input capture sensitivity, extra capture-duration delay, stereo-balance Ping-Pong and pitch-shift aliasing are known deferred findings, not silently fixed here.

## Runtime/headroom intent
No additional audio buffers or voice ceiling increase. Added small lifecycle/timer bookkeeping, with more actual work possible because busy input now produces playback. Hardware processing margin is unknown. Peak guard stays unchanged. CORE 0.3-0 source is unchanged.
