## 2. Why this change happened

The three-custom-unit architecture repeatedly failed DC's MkI load-balance testing. DC approved CORE + FIELD and the six review improvements before implementation: precise admission, bounded sounding voices, capture ownership, foreground level hierarchy, fixed expiry and shared bloom. New improvements outside that scope require a pause. No additional product features were added.

## 3. What changed

Added `effects/lattice-field/` with a two-seed stereo finite phrase scheduler and shared bloom, `tests/lattice-field/` running the actual DSP under a minimal host API shim, and `.github/workflows/build-lattice-field-test.yml` for host checks plus original-MkI ARM builds. Updated the current spec/system/history.

Implementation constants and the exact phrase tables are recorded in section 22 of `LATTICE_FIELD_SPEC.md`. Key values: 2 owned seeds, 6 events per seed, 8 voice slots/4-admission ceiling at fastest divisions, 96-sample retirement, 4096-frame maximum stereo fragment, fixed TTL of 10 initial clock ticks + 4096 frames, .82 spatial feedback, and a 6–8 second final bloom-rest envelope. Active audio is never held in a slot excluded from servicing by a later budget reduction.

## 4. Sound-quality intent

Four clear unison answers precede two sparse +7/+12 ghosts. Foreground events retain source definition; stage-dependent sends shift the phrase toward warm BODY and quieter HALO. Every played event feeds the same bloom. Stereo dry is untouched at zero MIX for normalized finite input. Middle MIX is intended to make the first two answers obvious without an over-loud cloud. Reverse and stutter edges, seed retirement, normalization, bloom ducking and MIX use fades/smoothing. Perceived fullness, aliasing and musical identity still require physical listening.

## 5. Runtime and headroom intent

Declared audio buffers use 139,264 SDRAM bytes (136 KiB). Static state/executable use is reported by the ARM linker in the artifact. There is no heap allocation or audio-rate trigonometric function. Event scheduling does not allocate future sounding voices. One compact bloom replaces the former standalone ECHO + SPACE combination. These choices are runtime design intent, not measured MkI CPU margin.

Separate foreground/ghost/send normalization protects first-order responses. The wet stereo guard operates above .90 FS; dry is reduced only by MIX except emergency output clipping on invalid/excess input. Desktop ordinary-level input had zero wet-guard interventions; this does not establish every-source headroom or absence of audible hardware pumping.

## 6. Build / automated test result

The initial optimized desktop test passed all 32 mode/division lifecycle combinations, isolated-note wet audibility, held-input no-recapture, release/rearm, immutable deadlines, sample-clock wrap, dense replacement ownership, control sweeps, invalid input/tempo, lifecycle reset and ordinary-input headroom.

Address/undefined-behavior checks and ARM compile/package are required by the new CI workflow. Leak detection is not needed for the allocation-free DSP; this managed local environment runs under tracing that prevents LeakSanitizer, so local ASan/UBSan uses `ASAN_OPTIONS=detect_leaks=0`. CI uses its normal sanitizer environment. Do not infer a CI result from this pre-CI report; consult the subsequent result report and artifact provenance.

## 7. Physical MkI result

None for FIELD. DC will test the hardware package. Existing CORE/ECHO/SPACE feedback is historical context, not a FIELD pass.

## 8. Result classification

Implementation candidate / hardware gate OPEN. A successful ARM package is **BUILD ONLY**, never PASS solely from desktop or CI checks.

## 9. What we learned

The phrase lifecycle must include capture storage ownership, voice retirement, immutable expiry and input admission. Finite event count alone is insufficient. A processor downstream of CORE sees CORE's output, including freeze attacks; no-self-recapture must not be confused with rejecting upstream generated audio.
